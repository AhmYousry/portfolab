| D-028 | Phone number collected on the checkout page is sent to Paymob only (required billing field), never stored | Data minimization | Accepted |
| D-029 | Google and GitHub sign-in use a server-side authorization-code flow. PKCE is S256. The state is random, sent as an HMAC-signed HttpOnly cookie (`Path=/api/auth/oauth`), and tied to a one-use `OAuthAttempt` row that expires in 10 minutes and is consumed atomically. Google ID tokens are verified with `jose` (signature, iss, aud, exp, nonce, azp, `email_verified`). For GitHub the email must be the verified primary from `/user/emails`. Scopes are `openid email profile` and `read:user user:email`. Provider tokens are never stored. | Standard OAuth 2.1/OIDC hardening. `jose` is the one new dependency. | Implemented; activation **blocked on owner** (client IDs/secrets) |
| D-030 | Accounts are never auto-linked by email. A provider email that already belongs to a user gives a generic "use your original method" message. New OAuth accounts need the privacy box checked on `/signup`; the start POST is CSRF-protected and carries the consent. A login-page attempt from an unknown identity creates nothing. OAuth users get an Argon2id hash of a random secret, which keeps `passwordHash` required. In password mode, "Forgot password" can set a password. In social mode, recovery uses the original provider account. Provider links are deleted when the account is deleted. | Prevents account takeover through unverified or recycled provider emails, and keeps privacy consent explicit | Accepted |
| D-031 | OAuth callbacks are built from `APP_URL` (bare origin), not `API_PUBLIC_URL`. | The binding cookie is set on the web origin. The API is same-origin behind Caddy and the Vite proxy. | Accepted |
| D-032 | The zero-budget beta uses one Render Free web service and Neon Free. `render.yaml` selects `AUTH_MODE=social`, disables checkout, and serves the built web app and API from the same origin. Account deletion requires a fresh OAuth round trip for the linked identity and a five-minute, single-use grant bound to the original session, followed by explicit confirmation. | Owner requires zero spending and has a GitHub account. No mail provider or purchased domain is needed for this deployment. | Implemented locally; live activation needs owner accounts and OAuth credentials |
